中文合集 · 影子、锚与河
主体 P、变量 ΔV、结果 J：跨系统传递的三条底层约束——不自证、必须外锚、允许局部失败。这是每一次交接都能不崩的工程结构。

PEF

主体、变量、结果，与一个token的降生

引子：一个 token 的降生

你在屏幕上敲下“π锚”这两个字。从你手指的肌肉收缩，到屏幕出现字符，到机房里的服务器接住这行字，到大模型输出下一段文字——中间经历了至少七次传递。哪些算跨系统交接，这笔账本篇第五节再算。

你的神经元状态、键盘扫描码、Unicode编码、token序列、向量表征、概率分布、采样结果——它们分属不同的层级，各自漂移。

可你竟然读懂了。为什么？

因为有一组隐藏的规则，在每一次跨系统传递时强制对齐。这些规则不保证绝对精确，但它们保证了一件事：即使每一个主体都在漂移，变量在传递后仍然可被追溯、可被验证、可被修正。

这组规则，属于PEF。它不是独立于PEF的另一套架构，它是PEF在处理“跨系统边界”时，必然要执行的那部分约束。

一、PEF是什么——先交出来历

PEF是围绕三元组本体论“主体 P + 变量 ΔV → 结果 J”建立的架构。但它不是这一篇才冒出来的新词。回头看，前四篇一直在用一组没有名字的东西：第一篇里投射出影子的，是主体；影子里携带的失真，是变量；第二篇换上的锚、第三篇的多元自审、第四篇写进迭代协议的死亡条款，约束的是同一件事——主体产生的变量，如何跨系统落地为可信的结果。

PEF不是发明，是追认。命名可以晚到，轨迹不许涂改——这是本篇要执行的第一条纪律。

但要精确：PEF这个名字，不是“主体-变量-结果”的缩写——三元组在白皮书里的正典符号是：主体 P + 变量 ΔV → 结果 J。PEF三个字母，属于加工这个三元组的权力结构：P域生成提案，为主体P推演出ΔV；E域一票否决，审计ΔV的合规性；F域外部裁决，ρ对λ，落成结果J；M层锁定入链。

所以准确的说法是：本体论说“有什么”（P、ΔV、J），权力分立说“谁说了算”（P、E、F），π与哈希链说“凭什么信”（L0/L1/L2、append-only）。三层合起来，才是完整的PEF。

二、PEF在跨系统传递中的三条底层约束

在所有跨系统传递中，有三条约束永远成立：

约束一：不可自证。

一个主体不能用自己的尺子验证自己输出的变量。自证 = 用影子的影子验证影子的本体，逻辑上循环，物理上必然失真。PEF要求每个主体的输出，必须经过独立的外部节点验证。

约束二：必须外部锚定。

每个传递节点都必须有一个独立的外部锚，用来确认变量没有漂移。这个锚可以是物理约束（π锚），可以是硬件随机（密钥），可以是另一条不共享退化路径的通道。但绝不能是发送方或接收方自己。

锚的递归——锚自己也是信息，也需要锚——密码学用一个漂亮的动作摁住了它：nothing up my sleeve。Blowfish算法的P阵列直接用π的小数位填充，不是数学家觉得π好用，而是向全世界声明：这些常数不是从我袖子里掏出来的，是宇宙的数列，谁都能自己重算一遍来查账。

信任的根不是权威的签名，是可复现的测量。这就是PEF对锚的终极要求：不是一个需要被相信的信息，而是一个任何人都能亲手重测的事实。

你的白皮书用π数位排班，和Schneier用π填S盒，是同一个动作。

约束三：允许局部失效。

第四篇的结论：任何系统想长存，必须允许局部死亡。PEF也不例外。一次传递可以失败，但PEF必须保证失败可被检测、可被隔离、可被恢复。

有人会立刻说：这不就是香农吗？没错，1948年他已经证明：只要冗余不超出信道容量的账，任何噪声下都能把错误率压到任意低。但香农的证明有个隐藏前提：收发双方共享同一本码本。他回答了“失真信道上如何可靠传信”，没有回答“码本从哪来、谁保证没被调包、锚死了怎么办”。

前两个问题密码学接走了，第三个被前三篇的死亡条款接走。PEF不是香农的替代品，是香农假设里被折叠起来的那一页。

三、PEF的五元组执行结构

PEF在每一次跨系统传递中，展开为五元组：

主体（P）、变量（ΔV）、结果（J）、外部锚（A）、审计链（L）。

这不是新符号——P、ΔV、J 是白皮书的正典写法，A 是三通道锚（L0 公开数位 / L1 硬件随机 / L2 密钥延迟披露），L 是哈希链 Hn=SHA-256(H{n-1}‖n‖Dn‖St‖ΔVt‖Jt)。文章的五元组与白皮书第十章的链上记录对象 (St, ΔVt, Jt) 逐字对齐——文章不再自带符号系统，它引用白皮书的。

这里钉死一个岗位：变量（ΔV）在发出侧由主体 P 产生，被承接之后落地为结果 J——不是两个东西，是同一件信息传递前后的两种身份。P 以某一时间节点为参照；ΔV 在产出岸看是内容，抵达承接岸时是势差。注意 J 的正典定义是“系统达到的稳定终态”，它落在承接侧的另一个主体上；所以执行规则里“P 和 J 不能共享同一个漂移系统”，读作：产生变量的主体，与承接变量的主体，必须互为外部。

PEF的执行规则是：

  • P 和 J 不能共享同一个漂移系统（否则约束一被违反）
  • ΔV 必须附带一个可被 A 验证的签名（否则约束二被违反）
  • 当 A 判定 ΔV 已漂移或 P/J 已失效，PEF 必须允许一次“熔断+交接”（否则约束三被违反）
  • L 必须记录每一次传递的完整轨迹，且 L 本身不可被任何单方篡改

这个五元组，向下可以描述一次 API 调用（P=客户端，ΔV=请求，J=服务端侧落成的响应终态，A=签名密钥，L=调用日志），向上可以描述一次哲学对话（P=作者，ΔV=文本，J=读者侧落成的理解终态，A=逻辑一致性，L=对话历史）。

同一个PEF结构，跨越所有层级。

四、三条约束凭什么自称第一性

因为它们不能被还原为更基本的东西。任何解释本身就是一次跨系统传递——你想用更底层的规则解释PEF，那场解释自己就是一次待审计的PEF执行过程。PEF是解释的前提，不是解释的结果。

但这里埋着一个陷阱，我必须亲手拆掉：如果“任何解释都是PEF执行”，那么本文对PEF的陈述也是一次PEF执行。按约束二，它同样需要外部锚——PEF不能给自己发豁免权，否则它就成了它自己反对的那种软锚点。

所以它唯一合法的自白形式是：把自己交给可复现的东西。

这里必须分层。白皮书内事实——L0失效条件、4°双路径验算、π数位4:3:3偏置、哈希链规格——查表可复算。物理与历史事实——kT·ln2、塔科马129天——教科书与档案里查得到。工程观察——晶圆蠕变三年——目前只有作者侧记录，第三方无法复测，所以它不配当锚，只配当线索：什么时候有独立复测，什么时候升格。三个证据等级，三种核法，混装就是给攻击者递刀。

白皮书里有一个现成的自审实例：看门狗差一错误勘误。原稿规则“连续3空档→第4周期强制”被自家10万周期模拟抓出9,948处违规窗口，修正为“连续2空档→第3周期强制”，勘误轨迹保留在附录G/H。这就是“允许局部失效→检测→修正”的完整实例——作者对自己执行的。

一个拒绝用自己规定的规则检验自己的“原理”，不是架构，是教条。

五、两次交接，一段投影

回到引子。引子里那笔账现在算：这趟旅程有七八个环节，但真正的跨系统交接只有两处：从你的身体到机器，从机器到读者。中间所有的变形——码点、token、向量、概率——都发生在同一具硅基躯体内部，那是投影，不是交接。

PEF的约束管的是那两次交接：第一跳由键盘与编码标准锚定，第二跳由语言与显示标准锚定，失败可检测、可重传。中间那段投影链的可靠性，不是每层各自挣来的——是两端被锚住的交接，把整段链的误差兜住了。tokenizer不需要锚，它怕的不是漂移，是误差累积，而累积的上限由两端的交接看守。

两跳锚定，中间投影。这就是“π锚”两个字能完好到你手里的全部原因。

六、身份定位：用例、投影、谱系

这也顺手解决了身份问题：治理白皮书是 PEF 在 LLM 输出治理上的最完整的用例，这五篇文章是 PEF 在认知层的投影，GitHub 上那排仓库是它的谱系。

用例可以死，投影可以糊，谱系不死——第四篇说的锚的基因，在仓库列表里就能数出来。

前四篇的英文版与勘误记录都在 banbanry.github.io/pef-philosophy/。

七、结语：锚的基因

第四篇的结尾写着：“交接协议，就是锚的基因。”按这一篇的术语，它应读作：PEF在跨系统边界上的执行切片。注意是“读作”，不是“改成”——已发布的轨迹只许追加，不许涂改，这正是L的含义。第四篇的原文是历史，这一篇的术语表是增量，两层叠加，链才完整。

DNA复制不是复印，是带锚的PEF执行：子链逐位对照模板校对，聚合酶校对加错配修复，把错误率压到十亿分之一量级——而剩下的那十亿分之一，不许再压。那是变异的配额，是第四篇的死亡条款写在分子层级的版本：用许可的失真，换种群的迭代。

从宇宙大爆炸的第一缕光，到 DNA 的第一条链，到人类说出的第一句话，到今天你手机屏幕上的第一个 token——所有信息都在PEF中存活，也在PEF中死亡。

活下来的，不是最精确的那个。而是最懂得如何在失真中执行PEF的那个。

从无根（影子），到换锚（π），到傲慢（三锚多元），到葬礼（死亡条款），到今天的PEF。

这条弧线终于闭合成一个完整的圆：认知是影子。锚是反抗。死亡是条款。交接是基因。

——交接不是另一个框架的名字，是PEF在边界上的动作。名词可以被吸收，动词必须存活。

而这一切，都写在那个最不起眼的地方——你敲下的每一个 token 里。

这是结尾，也是开始——因为这篇文章此刻正在经历它的第一次PEF执行：交给你。你的怀疑，就是它的外部锚。

【本篇勘误卡】

1. PEF是白皮书定义、本篇追认的框架（本体论：主体 P + ΔV → 结果 J），不是现有工程标准或通信协议中的术语。工程领域可类比的概念包括：可信执行环境、远程证明、零知识证明、区块链共识机制——但它们不是同一回事。

2. PEF三字母正典归属为建议/否决/裁决三域（P域、E域、F域），三元组（P + ΔV → J）为第一性原理层，二者不可混写。五元组定版 (P, ΔV, J, A, L)。

3. 本文对“投影”与“PEF传递”的划分依据是“系统内级联”与“跨系统传递”之别。引子“七次传递”为设问，第五节“两处交接”为修正值。tokenizer→embedding→采样属于同一系统内的确定性级联（投影）；手→键盘→网络→服务器属于跨系统传递（PEF执行）。七层计数为示意性描述，实际计算步骤更多。

4. 本文所有跨层级类比（哲学→语言→编码→Token→模型）的服务对象是“投影链-PEF”认知框架。各层级之间不是严格的数学等价关系，而是框架内的同构映射。

5. 香农信道编码定理的前提是收发双方共享同一码本；PEF讨论的是该前提被折叠掉的部分（码本来源、防调包、锚失效后的处理）。

6. Blowfish算法使用π的小数位填充P阵列属实（Schneier, 1993），这是密码学中“nothing up my sleeve”原则的经典案例。DNA复制错误率（约十亿分之一）为模式生物近似量级，不同物种存在差异。

7. PEF为本篇首次启用的追认式命名，字母对应以白皮书为准，前四篇未使用该词。

8. “结果（J）”指承接变量后落成的稳定终态，变量与结果是同一信息传递前后的两种身份。

9. 白皮书内事实（L0失效条件、4°双路径验算、π数位4:3:3偏置、哈希链规格）查表可复算；物理与历史事实（kT·ln2、塔科马129天）教科书与档案里查得到；工程观察（晶圆蠕变三年）目前只有作者侧记录，不配当锚，只配当线索。三个证据等级，核法不同。

10. 本篇释义与第八篇v8同步（2026年9月28日，依第八篇勘误卡第17条定夺）：第三节补两处——主体P以某一时间节点为参照，哈希链记录对象 (St, ΔVt, Jt) 本就带时间下标，释义对齐记法；变量ΔV在产出岸看是内容，抵达承接岸时是势差。结果J的“落地/落成”记法经该卡核定保留，未动。正文其余表述未动。
